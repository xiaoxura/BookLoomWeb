# txt2book 开发计划

| 项 | 值 |
| --- | --- |
| 文档版本 | 1.0 |
| 对应代码 | v0.2.0（M1–M4 已发布） |
| 更新日期 | 2026-11-04 |
| 状态 | v0.2.0 已发布，进入维护 |

本文把「校对与编辑」「格式与内容」「导出与排版」「工程与体验」四块整理成可执行的需求清单，给出实现要点、验收标准和里程碑建议。规模用 S / M / L 表示：S 约半天内，M 约 1–2 天，L 约 3 天以上（含测试）。

## 1. 背景与现状

txt2book 目前已经打通「导入 → 识别 → 校对 → 排版 → 导出」的主干：

- TXT / EPUB 双向导入，EPUB 保留卷章层级与封面
- 章节识别（标题形态 + 密度）、漏章诊断、人工校对
- EPUB 3 / EPUB 2 打包，TXT / Markdown 导出
- 批量转换、本地草稿、站内公告、更新日志
- 排版：章号单独一行、附加 CSS、嵌入字体、行高/段距/缩进/字体/对齐
- 两种封面：竖排书名、Orly 风格色块（本地生成）

代码结构（约 9700 行，含样式与测试）：

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 文本层 | `src/core/text.ts` | 编码检测、清洗、并段、广告行过滤 |
| 章节层 | `src/core/chapters.ts` | 标题打分、卷/章切分、目录页剔除、漏章候选 |
| 编辑层 | `src/core/edit.ts` | 分章、合并、删除、升降级 |
| 规则 | `src/core/rules.ts` | 站点预设、自定义规则校验与编译 |
| 导入 | `src/core/import/` | 格式探测、EPUB 读取 |
| 导出 | `src/core/export/` | EPUB 打包、TXT / Markdown 写出 |
| 封面 | `src/core/cover.ts` | Canvas 封面生成、上传图裁切 |
| 草稿 | `src/core/draft.ts` | IndexedDB 草稿、原文、字体 |
| Worker | `src/worker/` | 解析与打包 |
| UI | `src/main.ts` | 启动、草稿会话、Worker、批量转换（M2 后约 1690 行） |
| 渲染 / 事件 | `src/app/` | 状态、DOM 引用、渲染、事件、导出、快捷键 |

现状中与后续需求直接相关的缺口：

- 编辑只有 4 处一次性「撤销」toast（合并、删除、设为标题、分章），没有通用撤销栈（M1 已补：`core/history.ts`）
- 正文清洗只有固定的行级广告过滤，没有用户自定义替换（M1 已补：`core/replace.ts` + 清洗面板）
- 「疑似漏章」只判断标题形态，不校验章号连续性（M1 已补：`core/audit.ts`）
- 草稿只保留一本（`draft.ts` 的 `KEY = 'current'`）（M2 已补：IndexedDB v2 书架）
- EPUB 导入会丢弃图片（`import/epub.ts` 的 `SKIP_TAGS` 含 `img`）
- 元数据只有书名、作者、语言（`types.ts` 的 `BookMeta`）
- UI 测试只有一个大 smoke（M1 已扩充撤销 / 替换 / 体检 / 快捷键场景，T2 仍待做）
- 界面文案全部硬编码中文

## 2. 规划原则

1. **本地优先**：不引入后端、不上传文件；新增能力优先在浏览器内完成。
2. **增量可发布**：每项功能独立可用，不要求大版本一起上线。
3. **可回归**：每项功能都补单测或 smoke 场景，旧草稿必须能恢复。
4. **控制依赖体积**：新增依赖要评估 gzip 后体积，词典、字体这类大资源按需加载。
5. **不做伪需求**：和定位冲突的能力（云同步、DRM 解密、MOBI）明确不做。

## 3. 需求明细

### 3.1 校对与编辑

#### E1 通用撤销 / 重做（P0，S–M）

- **现状**：`main.ts` 里已有 `snapshotChapters()` / `restore()`，但只用于分章等 4 个一次性 toast 撤销，离开提示就无法回退。
- **目标**：所有章节编辑（改标题、合并、删除、升降级、批量操作、替换）都可撤销/重做。
- **方案**：
  - 在 `main.ts` 增加 `history: Array<{ chapters: Chapter[]; activeId: string | null; label: string }>` 与游标，`commitChapters()` 入栈（上限 50），批量操作合并为一步。
  - `restore()` 改为从历史栈恢复；保留 toast 的「撤销」按钮，改为调用统一入口。
  - 快捷键 `Ctrl/Cmd+Z`、`Shift+Ctrl/Cmd+Z`；目录面板增加撤销/重做按钮（可选）。
  - 撤销后触发 `scheduleDraftSave()`，不额外写草稿历史。
- **验收**：连续 10 次编辑可逐步回退；撤销到初始状态再重做；刷新后草稿是最后一次状态。
- **风险**：历史栈与草稿自动保存的时序；大章节快照的内存占用（50 步 × 章数，必要时降到 20）。

#### E2 批量替换 / 清洗（P0，M）

- **现状**：只有 `isAdLine()` 的固定规则和规则里的 `drop` 整行删除，无法处理「替换」和复杂残留。
- **目标**：对全书标题/正文做查找替换，支持正则、预览命中、执行前快照。
- **方案**：
  - 新增「清洗」面板：查找、替换为、范围（标题/正文/全部）、区分大小写、正则开关。
  - 预览显示命中数量与前若干条前后文；执行前调用 `snapshotChapters()`（接入 E1）。
  - 执行放在主线程即可（百万字量级的替换一般在可接受范围内），但要防灾难性回溯：限制输入长度与正则长度，超时给出提示。
  - 结果写回 `chapters[].title` / `paragraphs`，随后触发诊断与草稿保存。
- **验收**：替换计数与预览一致；撤销可恢复；特殊字符（全角空格、换行）可正常处理。
- **风险**：正则回溯导致卡顿；替换后章节标题与正文边界变化需要重新诊断。

#### E3 全书体检 + 章号校验（P0，M）

- **现状**：`findHeadingCandidates()` 只找「像标题但没被识别」的段落，不检查章号是否连续。
- **目标**：一次扫描给出结构问题，并支持「按顺序重编号」。
- **方案**：
  - 新增 `src/core/audit.ts`，输出问题列表：章号缺号（第 1、2、4 章）、章号重复、空章节、标题重复、单章异常长/短、卷内无章、疑似广告残留（复用 `isAdLine`）。
  - 中文数字与阿拉伯数字统一归一化后比较；卷号单独一套。
  - 「重编号」保留原数字风格（中文/阿拉伯），只修章号部分，标题不动；执行前快照。
  - UI：现有诊断面板扩展为分类列表，点击可定位到对应章节/段落。
- **验收**：构造缺号/重复/空章样例，问题列表准确；重编号后章号连续且标题不变。
- **风险**：番外、序章、完本感言等特殊章节不参与连续编号；部分书章号本身有特殊含义，重编号必须手动触发。

#### E4 章节拖拽排序与多选（P1，M）

- **现状**：只能升降级、合并、删除，不能调整顺序，也不能批量操作。
- **目标**：拖动章节改变顺序；多选后批量升降级、合并、删除。
- **方案**：
  - 目录列表用 Pointer Events 实现拖拽（桌面 + 移动端），拖动时显示插入位置。
  - `state.selectedIds: Set<string>`，`Shift` 连选、`Ctrl/Cmd` 点选；批量操作条复用现有 selection-bar 样式。
  - 拖拽结果直接重排 `state.chapters`，通过 `commitChapters()` 入历史。
- **验收**：拖到卷内/卷外时层级规则明确；多选删除可撤销。
- **风险**：移动端拖拽与列表滚动冲突，需要长按阈值。

#### E5 快捷键（P1，S）

- **现状**：只有章节搜索、封面预览、公告三处 `keydown`。
- **目标**：常用操作可全键盘完成。
- **方案**：统一 keymap：`↑/↓` 或 `J/K` 切章、`/` 聚焦搜索、`Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+S` 导出、`Esc` 关闭浮层；输入框聚焦时不触发单键快捷键。
- **验收**：与浏览器默认行为不冲突（如 `Ctrl+S` 需 preventDefault）。
- **风险**：不同键盘布局与输入法状态。

### 3.2 格式与内容

#### F1 多草稿书架（P0，M–L）

- **现状**：`draft.ts` 只用固定 key（`current` / `source` / `font`），导入新书会覆盖旧草稿。
- **目标**：保留多本，书架页可切换、删除、重命名。
- **方案**：
  - IndexedDB 版本 1 → 2：新增 `books` store（`id`、`title`、`author`、`updatedAt`、`chapters`、`words`、`coverThumb`）。
  - `draft` / `source` / `font` 记录改为按 `bookId` 分键；启动进入书架或恢复上次打开的书。
  - 迁移：旧 `current` 记录转成一本 `books` 记录，失败时回滚并提示。
  - 容量：用 `navigator.storage.estimate()` 显示占用；删除书时清理 source/font。
- **验收**：三本书来回切换不丢改动；删除一本不影响其他；旧草稿自动迁移；无痕模式有降级提示。
- **风险**：schema 迁移；大文件 × 多本的配额；书架缩略图体积。

#### F2 繁简转换（P1，S–M）✅

- **现状**：无转换能力，导入什么字就用什么字。
- **目标**：导入时可选择「转简体 / 转繁体 / 保持原样」，标题与正文都生效。
- **方案**：`opencc-js`（或 wasm 版），词典按需加载；转换在 Worker 里做，结果只影响章节数据，不改原始文件；草稿记录转换选项。
- **验收**：常见简繁一对多（发/髮、干/乾）结果符合预期；关闭后不改变原文。
- **风险**：词典体积和许可需要先确认；港台用词差异不做。

#### F3 DOCX 导入（P1，M）✅

- **现状**：只支持 TXT / EPUB。
- **目标**：Word 稿可直接导入，按标题样式还原卷章。
- **方案**：fflate 解压，读取 `word/document.xml`；`w:pStyle` 为 `Heading1` / `Heading2`（含本地化「标题 1」）映射为卷/章；普通段落进正文；图片先忽略（见 F4）。
- **验收**：带标题样式的 DOCX 能拆出正确层级；无样式的 DOCX 退化为单章并提示。
- **风险**：样式名随 Office 语言变化；复杂表格/文本框内容丢失需在提示里说明。

#### F4 EPUB 导入保留图片（P2，L）

- **现状**：`SKIP_TAGS` 直接丢弃 `img`，插图本导入后只剩文字。
- **目标**：保留章节内图片，导出时一并打包。
- **方案**：需要先扩展章节模型（`paragraphs: string[]` → 支持 `{ type: 'text' | 'image', ... }`），牵涉草稿、预览、TXT/Markdown 导出和 EPUB 打包；图片二进制存草稿要评估体积。
- **验收**：带图 EPUB 导入导出后图片仍在正确位置；TXT 导出用占位符（如「[插图]」）。
- **风险**：模型改造面大，建议等 F1 书架完成后再做。

#### F5 导出 DOCX / 单文件 HTML（P2，S–M）✅

- **目标**：给需要继续编辑或分享的人。
- **方案**：DOCX 用最小 OOXML（`document.xml` + `styles.xml` + `[Content_Types].xml`）打包，标题用 Heading 样式；HTML 输出单文件、内联 CSS、图片可选内嵌。
- **验收**：Word 打开无修复提示；HTML 双击可读、目录可跳转。

### 3.3 导出与排版

#### X1 元数据扩展（P1，S）✅

- **现状**：`BookMeta` 只有 `title` / `author` / `language`。
- **目标**：支持简介、系列、出版社、标签、出版日期。
- **方案**：`BookMeta` 增加可选字段；`buildEpub` 输出 `dc:description`、`dc:publisher`、`dc:subject`、`dc:date`、`belongs-to-collection`（EPUB 3）；草稿兼容旧数据。
- **验收**：Calibre / Kindle Previewer 能读到系列与简介。
- **风险**：EPUB 2 对系列字段支持有限，只在 EPUB 3 输出。

#### X2 内嵌目录页（P1，S）✅

- **目标**：正文前生成一页可点击的目录，而不只是阅读器的 nav。
- **方案**：复用 `navTree()` 生成 `text/toc.xhtml`，插入 spine 首位（封面之后）；EPUB 2 同样生成；样式沿用卷/章层级。
- **验收**：点击目录跳转正确；不重复计入章节数。

#### X3 封面编辑器（P2，M）✅

- **目标**：在两种模板基础上改配色、构图、字号、作者位置，实时预览。
- **方案**：把 `cover.ts` 的绘制参数抽成 `CoverOptions`（配色、版式、字号），UI 提供少量预设 + 实时 canvas 预览；导出仍为 JPEG；草稿保存参数。
- **验收**：切换参数后导出图与预览一致；恢复自动封面不报错。

#### X4 字体子集化（暂缓）

需要 fonttools/harfbuzz 的 wasm 支持，收益是体积，成本高；当前保留「嵌入整字体 + 体积提示」即可，不在本期范围。

### 3.4 工程与体验

#### T1 拆分 main.ts（P0，M）

- **现状**：`src/main.ts` 约 2254 行，状态、渲染、事件、导出混在一起。
- **目标**：按职责拆分，降低后续功能成本。
- **方案**：拆为 `src/app/state.ts`（状态与 reducer 式更新）、`src/app/render/*`（列表/预览/设置）、`src/app/events.ts`、`src/app/export.ts`；每步保持行为不变，用 smoke 回归。
- **验收**：拆分后单测与 smoke 全绿，包体积无明显增长。
- **风险**：纯重构周期长，建议和 E1/E3 一起做，避免多次返工。

#### T2 场景化 UI 测试（P1，M）

- **现状**：`scripts/smoke.mjs` 是单个大流程，失败定位成本高。
- **目标**：按场景拆分，失败能直接看出是哪块坏了。
- **方案**：拆成 landing / import / workspace / export / batch / draft / mobile 场景，共享启动与下载 helper；CI 先 build 再跑 smoke。
- **验收**：每个场景可单独执行；总耗时不超过当前 smoke 的 1.5 倍。

#### T3 国际化（P2，L）

- **现状**：文案硬编码在 `index.html`、`changelog.html`、`main.ts`、`notice.ts`。
- **目标**：至少支持中文 / English。
- **方案**：抽取 `src/i18n/zh-CN.ts` 与 `en.ts`，按 `navigator.language` 选择；HTML 静态文案改为占位或 JS 注入；日期/数字用 `Intl`。
- **风险**：文案量大，建议先做工作区（不翻译落地页指南）。

#### T4 移动端手势（P2，S–M）

- **目标**：左右滑动切换章节，长按选段。
- **方案**：在预览区用 Pointer Events 判定横向滑动（阈值 + 角度），与纵向滚动区分；不干扰选择段落。
- **验收**：滑动切章不误触；在 iOS Safari 与 Android Chrome 上表现一致。

## 4. 里程碑建议

| 里程碑 | 内容 | 依赖 | 出口标准 |
| --- | --- | --- | --- |
| M1 校对增强 | E1、E2、E3、E5 | 无 | 单测覆盖新逻辑，smoke 增加对应场景，旧草稿兼容 ✅ 已完成 |
| M2 书架 | F1、T1 部分 | 草稿 schema | 迁移测试通过，多书切换无数据丢失 ✅ 已完成 |
| M3 格式扩展 | F2、F3、F5 | M2 | 各格式往返用例，失败提示清晰 ✅ 已完成 |
| M4 导出增强 | X1、X2、X3 | 无 | EPUB 结构校验通过，Calibre 打开正常（已发布，人工验收建议补做） ✅ 已完成 |
| 持续 | T2、T4、F4 | — | 按季度评估，F4 需先定模型 |

依赖关系：E1 是 E2/E3/E4 的基础（都要入历史）；F1 是 F4 的前置（图片存草稿需要书架容量管理）；T1 建议在 M1/M2 期间穿插完成，避免 `main.ts` 继续膨胀。

## 6. 测试策略

- **单元测试**：每个新模块（audit、替换、导入器）必须有纯函数测试；fixtures 增加缺失章号 TXT、带图 EPUB、DOCX。
- **端到端**：smoke 拆场景后，M1 增加「撤销/重做」「替换」「体检重编号」场景；M2 增加「多书切换」；M3 增加「DOCX 导入」「繁简转换」。
- **兼容性**：每次改草稿 schema 都要跑迁移测试（旧数据 → 新数据 → 恢复）。
- **构建**：`npm run build` + `npm run validate` 保持通过。

## 7. 本期不做

- MOBI / AZW3（依赖 kindlegen 类外部工具）
- PDF 导入导出（字体子集化与重排成本过高）
- 云同步 / 账号体系（与本地优先定位冲突）
- DRM 解密
- 字体子集化（X4，暂缓）
